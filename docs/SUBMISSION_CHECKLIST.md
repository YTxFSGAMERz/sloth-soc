# Sloth SOC: Submission Checklist

Challenge: Hacktoberfest Open-Source AI Challenge: Week 3, "Slow and Steady". Deadline: **Oct 25, 2026, 11:59 PM PDT** (06:59 UTC on Oct 26). Re-read the official rules and FAQ yourself; this list summarizes the challenge page and does not replace them.

## 1. Eligibility and rules (human, 10 minutes)
- [ ] Rules and FAQ read, including "Can I use AI?", "Can I work on an old project?", and eligibility (age, region).
- [ ] The repo is brand new and its first commit falls inside the contest window.
- [ ] Deadline converted to local time and written down.
- [ ] Post will use the DEV submission template (adds `devchallenge` and `hf26challenge`).

## 2. Judging criteria to evidence map
| Criterion | Weight | Evidence to show |
|---|---|---|
| Writing quality | highest | Strong hook, clear story spine, figures with takeaway captions, honest limits, own voice (see `docs/DEVTO_POST_OUTLINE.md`) |
| Relevance to prompt and theme | high | Sloth framing; lazy payoff number (E6); demo; "why open" with proof (offline run, swap one config line, no per-token cost) |
| Creativity | high | Math decides and the LLM narrates; the tool detects injection attempts aimed at itself; slow-and-steady model-size finding |
| Technical execution | high | Tests, CI, deterministic eval, results with intervals, no-egress test, clean-clone quickstart |
| Partner technology | optional | See section 3 |

## 3. Partner categories: where to aim
| Category | Decision | Evidence for the post |
|---|---|---|
| Best Use of Gemma | **Yes (core)** | Local Gemma via Ollama; model-size sweep (E3); model swap by config |
| Best Use of TabPFN | **Yes if it works by end of Day 2** | TabPFN as a detector inside the wider pipeline; label-efficiency curve (E2); note the non-commercial weight license and the one-time login and download |
| Best Use of a .tech Domain | Optional (30 to 45 min) | Claim the free domain via the Hacktoberfest promos page; host a static project page with a sample digest and results; link it in the post |
| Best Use of Entire / session sharing | Optional | Link the saved agent session (see the challenge page's DevRelay note) and `BUILD_LOG.md` excerpts |
| Best Use of Sentry Agent Tracing | Only after the freeze criteria | Tracing sends data to a cloud service, which conflicts with the offline story; if used, synthetic data only, optional flag, say so loudly |
| Tinker, Temporal, others | Skip unless far ahead | Each needs real integration time; shallow use does not help |

Claim any credits or promo codes you actually need at hacktoberfest.com/my/promos.

## 4. Repo readiness
- [ ] README: pitch, screenshot, generated headline numbers, 60-second quickstart, architecture figure, why-open section, results block, red-team table, scheduling how-to, limitations and threats to validity, license and model terms, link to the post.
- [ ] `docs/` complete and consistent with the code; `docs/LICENSES.md` lists code, dependency, and model terms verified from official pages.
- [ ] `sloth-soc demo` and `demo --no-llm` work from a clean clone.
- [ ] `pytest -q`, `ruff check .`, `ruff format --check .` pass; CI badge green.
- [ ] Sample digests and figures committed under `examples/` and `results/figures/`.
- [ ] No real IPs, hostnames, usernames, logs, tokens, or secrets in the repo or screenshots.
- [ ] `BUILD_LOG.md` and `DECISIONS.md` present and tidy.
- [ ] Tag `v0.1.0` pushed.

## 5. Evidence readiness
- [ ] `results/E1..E6.json`, `RESULTS.md`, figures regenerated by `/run-evals` on the final commit.
- [ ] Red-team table for naive, structured, hardened, with failures listed.
- [ ] Offline proof: screenshot with the network disabled and the no-egress test passing.
- [ ] Hardware and versions recorded alongside every number.

## 6. Post readiness
- [ ] Follows the spine: hook, lazy payoff, idea, demo, design, attack on own tool, results, why open, limits, try it.
- [ ] Every number traces to `results/`; assumptions are stated next to estimates.
- [ ] Demo video or GIF included; cover image set.
- [ ] Read aloud; typos fixed; links tested in a private window.
- [ ] Written in the author's own voice.

## 7. Publish and after
- [ ] Publish with at least several hours of margin before the deadline.
- [ ] Re-open the live post in a private window and click every link.
- [ ] Post the link in the challenge launch thread and the MLH Discord if desired; answer comments.
- [ ] Winners are announced the week of Oct 26. Stop building; reply to questions and fix typos only.
